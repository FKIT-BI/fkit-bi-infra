# Демо-стенд: косметическая фабрика

Как наполнить Dev-стенд данными и провести показ. Справочники и оборудование создаёт релиз Analytics
`015-demo-enterprises` (применяется сам при раскатке Analytics), телеметрию — генератор через
`scripts/demo_generate.py`.

## Что есть на стенде

Смены: дневная 08:00–20:00 и ночная 20:00–08:00, `Europe/Moscow`.

### «Демо-склад готовой продукции» (`DEMO_WAREHOUSE`)

Участок отгрузки: сортировочный конвейер СК-12 и паллетообмотчик ПО-2. Сценарий `DEMO_WAREHOUSE`, 24 ч:
дневные и вечерние волны, обед, обрыв плёнки, ожидание транспорта, ночной простой, ТО обмотчика.

### Общее

- У машин паспорт, параметры, дерево узлов, 7–9 сигналов (интервал 10 с), норма выпуска, счётчики выпуска и брака —
  OEE, MTBF, MTTR и Парето потерь считаются без диагностик.
- Правила состояний одинаковые: «Авария» → авария (через 5 с), режим `SETUP`/`CIP` → переналадка,
  режим `MAINT` → плановая остановка, «В работе» и скорость выше 25% нормы → работа, иначе простой;
  без данных 2 минуты → нет связи.
- Справочники причин потерь: 12 у фабрики, 6 у склада. Ручных инцидентов нет — причины размечаются на показе.
- `DEMO_LIVE_ALARM` — 11-минутный сценарий перегрева гомогенизатора для живого показа.
- История доступна с локальной полуночи за 7 дней до раскатки релиза.

## Наполнение данными (один раз после раскатки)

На Dev-хосте из каталога deployment, с bootstrap-учёткой из Infisical — пароль не вводится и не попадает в историю
команд. Наполнение идёт около 75 минут, поэтому запускайте в фоне:

```bash
nohup env INFISICAL_DOMAIN=https://secrets.kitexp.ru infisical run --projectId='<project-id>' --env=dev --path=/github-actions -- python3 scripts/demo_generate.py > demo-generate.log 2>&1 &
```

Ход работы: `tail -f demo-generate.log`. Сначала можно посмотреть план без изменений — добавьте `--dry-run`.

Скрипт:

1. Активирует шесть демо-сценариев (генератор перепроверяет их на текущем оборудовании).
2. По очереди генерирует историю по каждому из пяти циклических сценариев — от начала покрытия машин до текущего
   момента. Генератор держит один исторический прогон одновременно; запись идёт около 1500 измерений/с,
   неделя по одному сценарию — 10–20 минут.
3. Сразу после истории сценария догоняет минуты, которые она заняла, и запускает бесконечный realtime-прогон,
   чтобы машины не уходили в «нет связи».

Запуск с рабочей машины тоже возможен — скрипт ходит только в публичный API по HTTPS и спросит логин и пароль:
`python3 scripts/demo_generate.py --url https://bi.kitexp.ru`. Не передавайте учётные данные по HTTP или IP.

Аналитика досчитывает интервалы и KPI за несколько минут после последней записи.

## Обслуживание

- **Повторный запуск безопасен.** Сценарии с идущим realtime пропускаются; если стенд стоял (перезапуск,
  остановленные прогоны), скрипт дозаполнит пропуск историей и снова запустит realtime.
- **Только оживить без истории:** `--no-backfill` — пропуск останется «нет связи».
- **Уже сгенерированный период не перезаписывается** — сырые данные только добавляются, пересекающуюся историю
  генератор отклоняет. Полностью «сбросить» демо можно только пересозданием БД стенда.
- **Отключить демо:** перевести предприятия `DEMO_COSMETICS` и `DEMO_WAREHOUSE` в статус «отключено» и остановить
  их прогоны в генераторе.

## Сценарий показа (≈20 минут)

1. **Портал** — два предприятия; выбираем фабрику.
2. **Обзор предприятия** — карточки 12 машин в реальном времени, счётчики по состояниям. Линия розлива шампуней
   заметно «краснее» остальных — к ней вернёмся.
3. **Рейтинг машин и KPI за неделю** — стабильная линия туб в лидерах, проблемная линия шампуней внизу.
   Переключение периода и смены (дневная/ночная).
4. **Дашборд машины** — моноблок розлива шампуней: текущее состояние, featured-сигналы (скорость, выпуск),
   карта состояний и хронометраж смены — видны частые короткие аварии.
5. **Потери и Парето** — по линии шампуней: аварии и простои пока «без причины».
6. **Разметка вживую** — в журнале интервалов выбираем аварию моноблока и назначаем причину
   «Застревание тары на конвейере», затем обрыв ленты этикетировщика — «Брак этикетирования» или
   «Неисправность дозатора». Парето и KPI пересчитываются.
7. **Каскад на линии кремов** — авария укупорщика: укупорщик в аварии, дозатор и этикетировщик в простое —
   потери видны и у соседей.
8. **Варочный участок** — партийное производство: на графике температуры гомогенизатора нагрев 25 → 75 °C,
   гомогенизация, охлаждение; мойка CIP считается переналадкой.
9. **Живая авария** (см. ниже) — карточка гомогенизатора уходит в аварию на глазах.
10. **Генератор** — сценарии линий, журнал прогонов. Копируем `DEMO_BOTTLE_LINE` в «плохую неделю»,
    меняем длительность фаз — копия создаётся отключённой и запускается отдельно.
11. **Админка** — паспорт и дерево узлов машины, правила состояний; резервный дозатор вне линий и тубонаполнитель
    ТН-80 с чек-листом готовности.

### Живая авария на гомогенизаторе

```bash
env INFISICAL_DOMAIN=https://secrets.kitexp.ru infisical run --projectId='<project-id>' --env=dev --path=/github-actions -- python3 scripts/demo_generate.py --live-alarm
```

Скрипт останавливает realtime варочного участка, запускает `DEMO_LIVE_ALARM` — 2 минуты норма, 3 минуты рост
температуры до 97 °C, 4 минуты авария, 2 минуты пуск — и затем возвращает участок в realtime. Пока идёт показ,
реактор-смеситель и водоподготовка без связи: на машине может работать только один realtime-прогон.
Запустите команду за 2–3 минуты до нужного момента. То же можно сделать из UI генератора:
остановить realtime `DEMO_PREPARATION`, запустить `DEMO_LIVE_ALARM`, после окончания снова запустить `DEMO_PREPARATION`.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| «Нет активных демо-предприятий» | Analytics с релизом `015-demo-enterprises` не раскатан или предприятия отключены. |
| `HISTORICAL_CAPACITY_BUSY` в логе | Кто-то запустил другой исторический прогон — скрипт ждёт и повторяет сам. |
| Прогон `FAILED` | Посмотрите ошибку в журнале прогонов генератора; для retryable-ошибок нажмите «Повторить» и перезапустите скрипт. |
| Машины «нет связи» | Realtime-прогоны остановлены (например, после перезапуска стенда) — перезапустите скрипт. |
| KPI пустые сразу после наполнения | Аналитика ещё пересчитывает — подождите несколько минут. |
