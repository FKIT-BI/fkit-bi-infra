- (direction) Validate the accepted PostgreSQL and telemetry design for correctness, normalization, throughput and read/write non-blocking behavior; do not implement fixes in product code.
- (decision) AD-1 adopts ports-and-adapters per Spring service with explicit module ownership and one shared PostgreSQL contract.
- (decision) AD-2 binds one physical PostgreSQL split into equipment, telemetry, analytics, incident and generator schemas; it prevents accidental coupling through public tables.
- (decision) AD-3 binds Analytics as the sole Liquibase and DDL owner; migrations must finish before Generator uses the shared schema.
- (decision) AD-4 binds writers by domain: Analytics owns equipment, projections and incidents; Generator owns generator state and append-only telemetry only.
- (decision) AD-5 binds normalized equipment relations and composite foreign keys at owner boundaries; JSONB is limited to validated display-only parameters that are not queried analytically.
- (decision) AD-6 binds raw telemetry to an append-only, intentionally denormalized hot path with batch-level idempotency and no per-measurement FK or unique index.
- (decision) AD-7 binds raw_measurement to daily UTC RANGE partitions on observed_at, one signal/time index per partition, no default partition and 90-day event-time retention.
- (decision) AD-8 binds read paths to committed projections and PostgreSQL MVCC; ingestion never computes projections and workers never lock raw rows for update.
- (decision) AD-9 binds short batch transactions of at most 1000 measurements, bounded pools and a nominal 30 measurements/s profile with 200/s sustained benchmark and 1000–2000/s throttled historical load.
- (decision) AD-10 binds partition DDL and retention outside the hot insert transaction, with future partitions created before writers need them.
- (decision) AD-11 binds distinct owner, analytics, generator and monitor database roles even while all data remains in one database.
- (constraint) Minimum environment is PostgreSQL 16 on SSD, 4 vCPU, 8 GB RAM, 100 GB minimum and 150 GB recommended; Kafka and external ETL are out of MVP.
- (assumption) Proposed payload_hash and restriction of Historical Run to the active 90-day raw window are review candidates, not yet accepted decisions.
- (event) Validation target distilled from the current specs and architecture documents; reviewer findings must be reported without silently changing accepted source decisions.
- (event) Reviewer gate completed with CHANGES REQUIRED: the PostgreSQL-first architecture is retained, but partition maintenance, durable handoff, idempotency content binding, retention races, resource bulkheads and migration lifecycle must be amended before implementation.
- (question) User approval is required to adopt the ten corrective decisions summarized in VALIDATION-REPORT.md before updating the architecture spine and source specs.
- (event) Validation reports written to VALIDATION-REPORT.md and VALIDATION-REPORT.html; source spine and accepted specs were not changed by the validate operation.
- (direction) Пользователь принял упрощённый MVP-вариант исправлений reviewer gate и попросил не вводить отдельные migration/maintenance services или несколько datasource pools.
- (decision) AD-3 уточнён: Liquibase запускает сам Analytics при startup через отдельные spring.liquibase credentials; readiness остаётся false до успеха, Generator стартует после Analytics readiness.
- (decision) AD-6 уточнён: idempotency key связан с canonical SHA-256 payload_hash; несовпадающий hash под тем же key является ошибкой.
- (decision) AD-7 уточнён: Historical пишет только внутри активного 90-day raw window по времени PostgreSQL; raw batch атомарно создаёт durable per-machine recalculation hints, а факт первого Signal use сохраняется вне retention.
- (decision) AD-10 уточнён: owner-owned SECURITY DEFINER routines с fixed search_path, topology advisory lock и короткими lock/statement timeouts создают и удаляют partitions; MVP использует обычный detach с retry, не DETACH CONCURRENTLY.
- (decision) AD-9 уточнён: Analytics использует один Hikari pool, а ingestion/calculation/recalculation/maintenance ограничены semaphores так, чтобы workers не занимали весь pool; Historical проходит storage preflight и останавливается при disk pressure.
- (decision) AD-4 уточнён: Component hierarchy mutations сериализуются lock Machine, Shift schedule mutations — lock Enterprise; Signal first use и semantic mutation используют один first-use lock protocol.
- (decision) Telemetry numeric contract фиксирует mode 1 REALTIME/2 HISTORICAL, quality 0 GOOD/1 UNCERTAIN/2 BAD, flags 1 OUT_OF_RANGE/2 CLOCK_SKEW; quality не дублируется flags.
- (decision) Hot-path strings bounded at producer IDs 128 and value_text 500; ingest_batch cleanup выполняется bounded chunks после retention/idempotency horizon.
- (version) Implementation baseline updates both Java services to Spring Boot 3.5.16, managed Liquibase 4.31.1 and PostgreSQL JDBC 42.7.11; PostgreSQL remains major 16.
- (event) User accepted the simplified corrective architecture package; architecture may be redistilled and source specs updated before continuing analytics design.
