# Digest — rollout and failure containment

- **Claim:** Infisical's official Compose walkthrough frames single-node Compose as suitable for evaluation/small deployments, not high availability, and calls out the application, Postgres and Redis as separate components. It recommends pinning image versions, HTTPS, and backing up the database plus encryption key. **Source:** Infisical, “Self Host Infisical with Docker Compose,” accessed 2026-10-12, https://infisical.com/videos/self-host-infisical. **Confidence:** medium (vendor guidance).
- **Claim:** Current code defaults to outbound PostHog product telemetry and in-app announcement fetching; both need explicit opt-out if the desired posture is minimized outbound data. This was confirmed directly in current source config; exact event payloads and all possible outbound destinations were not exhaustively audited. **Source:** Infisical `env.ts`, current `main`, accessed 2026-10-12, https://github.com/Infisical/infisical/blob/main/backend/src/lib/config/env.ts. **Confidence:** high for default flags; unverified for complete outbound inventory.
- **Claim:** A public deployment should be treated as a Tier-0 credential service even for a demo: protect the UI with strong unique admin credentials and MFA if supported, prohibit open signup after initial setup, keep DB/cache private, publish only HTTPS via the existing edge, and preserve encrypted DB + encryption-key backups. This recommendation follows the exposed UI/API architecture and GitHub's least-privilege/log audit guidance; it is an operational recommendation, not a vendor guarantee. **Sources:** Infisical self-host walkthrough above; GitHub secure-use reference above. **Confidence:** high recommendation basis.
- **Open question:** Host capacity is not measured. Project planning describes a 4 vCPU / 8 GB demo baseline; adding app + DB + cache could affect workload. Measure host free memory/disk and Docker usage before pulling/starting containers; enforce resource limits only after measuring actual idle/peak budget.
- **Open question:** Public hostname chosen provisionally as `secrets.kitexp.ru`; the DNS A record is currently absent and the existing cert covers only `bi.kitexp.ru`, `api.bi.kitexp.ru`, and `generator.bi.kitexp.ru`. These are project-state observations, not vendor research claims.
