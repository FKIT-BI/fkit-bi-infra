- (direction by user) Пользователь согласовал отдельный блок физической модели аналитических проекций: компактные read models, индексы под запросы и атомарная публикация.
- (capability by user) CAP-1: Система быстро отдаёт текущие значения сигналов и состояние машин; успех — current API читает одну запись на Signal/Machine и возвращает currency metadata.
- (capability by user) CAP-2: Система отдаёт timeline рассчитанных и effective состояний; успех — интервалы выбираются по Machine и времени без чтения raw telemetry.
- (capability by user) CAP-3: Система обслуживает исторические графики и показатели из минутных фактов; успех — API ограничивает чтение выбранными сигналами/machines и закрытым диапазоном.
- (capability by user) CAP-4: Система заменяет пересчитанный диапазон без частичного результата; успех — reader видит прежнюю committed проекцию до commit публикации новой.
- (decision by user) Текущая проекция сигналов хранится в telemetry.signal_current_value; машинные состояния, timelines, минутные агрегаты, dirty work, recalculation jobs, deadlines и staging принадлежат analytics schema.
- (decision by user) Хранимые read models: signal_current_value, machine_current_state, machine_state_interval, machine_effective_state_interval, signal_numeric_rollup_1m, machine_metric_bucket_1m и machine_loss_bucket_1m.
- (decision by user) analytics хранит только минутные rollups; часовые/дневные таблицы не вводятся. Line и Enterprise metrics суммируют машинные buckets и затем считают производные коэффициенты.
- (decision by user) Проекционные таблицы не партиционируются в MVP и хранятся весь срок demo-данных; автоматическое удаление не требуется.
- (decision by user) Natural keys: signal_id; machine_id; (machine_id,effective_from) для обоих interval timelines; (signal_id,bucket_start); (machine_id,bucket_start). Loss bucket уникален по (machine_id,bucket_start,state,loss_reason_id), включая равные NULL причины.
- (decision by user) Текущие typed values сохраняются отдельными nullable колонками DOUBLE/LONG/BOOLEAN/STRING для last received и last usable; JSONB не используется для расчётных значений.
- (decision by user) Проекции ссылаются обычными FK на стабильные сущности equipment/incident; raw_measurement остаётся без per-row FK.
- (decision by user) Стартовые индексы покрывают сигнал+время для signal rollup, машину+время для machine timelines/buckets и shift+shiftDate+machine+время для shift queries; индексы под reason-only/query shapes добавляются только при необходимости.
- (decision by user) Dirty range является durable unit фоновой обработки с lease; machine_evaluation_deadline содержит не более одной ближайшей строки на Machine; пользовательские recalculation jobs остаются отдельными адресуемыми ресурсами.
- (decision by user) Результаты длинного расчёта готовятся в staging, валидируются, затем intervals, current state, согласованные machine/loss buckets и currency metadata публикуются одной короткой транзакцией.
- (decision by user) Новая telemetry во время обработки создаёт follow-up dirty work; active publication range не меняется под работающим worker.
- (constraint by user) Читатели используют MVCC и committed projections; read API не берёт блокирующие row locks и не читает staging.
- (assumption by analyst) Для восстановления после сбоя staging хранится в обычных durable таблицах с ключом dirty-range work item и очищается после успешной публикации или отмены; worker может безопасно пересоздать неполный stage.
- (event by analyst) Coherence validation passed: физические ключи соответствуют согласованным логическим таблицам, nullable loss reason имеет однозначную уникальность, а read path отделён от staging.
- (event by analyst) Preservation validation passed: current freshness, calculated/effective timeline, 1-minute rollups, loss attribution, demo retention, line/enterprise aggregation и no-partition decision отражены в kernel или companion.
- (assumption by Analytics) Current effective state is read by joining machine_current_state to the unique open effective timeline segment; this avoids a duplicate current overlay row and serves both values in one SQL query.
- (assumption by Analytics) telemetry.signal_current_value keeps machine_id for machine current queries and uses a technical equipment.telemetry_signal UNIQUE(machine_id,id) plus composite FK to preserve owner integrity.
- (assumption by Analytics) PostgreSQL 16 UNIQUE NULLS NOT DISTINCT enforces loss bucket identity when loss_reason_id is NULL, avoiding a sentinel reason.
- (decision by Analytics) Current signal rows store last usable ingestBatchId and ordinal as well as last usable event/receive timestamps so the accepted deterministic order survives across batch updates.
- (decision by Analytics) Signal numeric rollup stores outOfRangeCount independently from source-quality counts; out-of-range overlaps the source-quality category and disqualifies usability.

- (event by Analyst) Final preservation validation: all accepted MVP boundaries, no-partition/no-hourly-tables choices, lifetime demo projection retention, current/timeline/rollup/loss models and publication semantics are preserved; no unresolved decision is hidden.
