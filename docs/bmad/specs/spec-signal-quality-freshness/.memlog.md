- (direction) Пользователь принял предложенную модель quality/freshness и попросил продолжить аналитику.
- (capability) CAP-1: Система поддерживает текущую проекцию последнего полученного и последнего пригодного значения сигнала; успех — out-of-order history не заменяет более новое текущее значение.
- (capability) CAP-2: Система классифицирует актуальность сигнала как NO_DATA, FRESH или STALE; успех — результат детерминирован по последнему пригодному observedAt, reference time и staleAfterMs.
- (capability) CAP-3: State calculation и rollup используют только пригодные значения; успех — UNCERTAIN, BAD и disqualifying flags остаются видимыми, но не заменяют last usable и считаются отдельно.
- (capability) CAP-4: Система определяет OFFLINE по отсутствию telemetry машины; успех — системная проверка имеет приоритет над пользовательскими правилами и использует offlineAfterMs с default 60 seconds.
- (capability) CAP-5: Frontend видит состояние и причины недоверия к данным; успех — current responses возвращают freshness, quality, timestamps и calculation currency metadata без ожидания перерасчёта.
- (decision) signal_current_value хранит last received и last usable values; freshness вычисляется, а не хранится как entity status.
- (decision) Freshness enum: NO_DATA when no usable value exists, FRESH before staleAfterMs, STALE after it; no effective lifecycle status is introduced.
- (decision) Usable requires source quality GOOD and no disqualifying validation flag; UNCERTAIN, BAD and OUT_OF_RANGE do not replace last usable.
- (decision) A signal referenced by StateRule must have staleAfterMs; when last usable becomes stale, the expression input becomes UNKNOWN.
- (decision) Numeric rollup statistics use usable samples only and preserve separate total/good/uncertain/bad/out-of-range counts.
- (decision) signal_current_value replacement orders by observedAt then ingestBatchId and ordinal for deterministic ties; older historical data affects only dirty-window recalculation.
- (decision) OFFLINE uses absence of any accepted machine telemetry for offlineAfterMs, defaults to 60 seconds, and is configured with the machine state calculation rules rather than per signal.
- (decision) Best-effort packet loss may cause STALE or OFFLINE; frontend exposes lastObservedAt, quality, freshness, state, dataThrough and calculatedAt.
- (constraint) Freshness is evaluated against event-time reference: wall-clock now for current view and requested timeline time for historical recalculation.
- (event) Coherence validation passed: five capabilities have intent and testable success; signal freshness, projection lag and lifecycle status remain distinct.
- (event) Preservation validation passed: last received/usable, quality eligibility, NO_DATA/FRESH/STALE, out-of-order behavior, OFFLINE policy, rollup counters and frontend currency fields are present; wrapper-only dialogue omitted.
- (event) Spec finalized after user direction to continue; no open questions remain in the quality/freshness block.
- (decision by user) Принятая физическая карта telemetry: sourceQuality отдельно кодирует GOOD/UNCERTAIN/BAD; validation flags содержат OUT_OF_RANGE и CLOCK_SKEW, без SOURCE_UNCERTAIN/SOURCE_BAD. Usable требует sourceQuality=GOOD и отсутствия OUT_OF_RANGE.
- (decision by user) Last usable current value сохраняет ingestBatchId и ordinal вместе с observedAt, чтобы deterministic tuple ordering корректно сохранялся между batch updates.
- (event by analyst) Quality/current projection re-derived and validated: sourceQuality is not duplicated by flags, OUT_OF_RANGE is disqualifying, and last usable tie-breaker fields are retained.
