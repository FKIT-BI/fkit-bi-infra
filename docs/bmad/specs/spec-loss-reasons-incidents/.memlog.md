topic: Каталог причин потерь и ручная классификация incidents
updated: 2026-10-10T19:36
---

- (direction) Пользователь согласовал все рекомендации блока LossReason/ManualIncident и попросил применять enum там, где набор действительно закрыт.
- (capability) CAP-1: Enterprise управляет каталогом причин потерь; успех — причины имеют стабильную identity/category/status, доступны исторически и проверяются при новом назначении.
- (capability) CAP-2: Пользователь одним ManualIncident задаёт state override, loss reason или оба эффекта; успех — условно обязательные поля дают однозначный effect type без второй сущности.
- (capability) CAP-3: Система детерминированно совмещает независимые state и reason intervals; успех — в один момент не более одного override и одной reason, но state-only и reason-only incidents могут пересекаться.
- (capability) CAP-4: Пользователь исправляет, закрывает или отменяет incident; успех — mutation сохраняет историю строки, создаёт dirty range и атомарно актуализирует effective/loss projections.
- (capability) CAP-5: Причина остаётся объяснимой при recalculation и data gaps; успех — attribution применяется только к IDLE/DOWN/SETUP/PLANNED_STOP, а RUN/OFFLINE и underlying data quality не переписываются.
- (decision) LossReason enterprise-scoped fields: id, enterpriseId, stable code, name, optional description, LossCategory, optional color, ACTIVE/DISABLED, timestamps.
- (decision) LossReason code и normalized name уникальны внутри Enterprise; code immutable всегда.
- (decision) LossCategory является закрытым Java/OpenAPI enum EQUIPMENT/MATERIAL/PERSONNEL/PROCESS/QUALITY/CHANGEOVER/EXTERNAL/OTHER и хранится в PostgreSQL как VARCHAR, не native DB enum.
- (constraint) LossReason — пользовательский справочник и не является enum; enum применяется только к закрытым техническим наборам, изменяемым вместе с кодом.
- (decision) После первого использования category immutable; name/description/color остаются изменяемыми, а история показывает их текущие display values без версий.
- (decision) DISABLED блокирует новое назначение, но не прекращает existing/ongoing incidents и не меняет историю; reactivation разрешена.
- (decision) isPlanned удалён: plannedness выводится из effective state, а не дублируется причиной.
- (decision) UNCLASSIFIED означает null reason и не хранится как LossReason; OTHER является только synthetic analytical category.
- (decision) Unified ManualIncident fields: id,machineId,from,nullable to,nullable stateOverride,nullable lossReasonId,nullable comment,nullable author,createdAt,updatedAt,cancelledAt.
- (constraint) ManualIncident требует stateOverride или lossReasonId; stateOverride допускает только SETUP/PLANNED_STOP.
- (decision) Response effectType вычисляется как STATE_OVERRIDE, LOSS_ANNOTATION или STATE_OVERRIDE_WITH_REASON и не хранится.
- (decision) Reason attribution применяется к effective IDLE/DOWN/SETUP/PLANNED_STOP и игнорирует RUN/OFFLINE portions без изменения state.
- (decision) Reason-only create требует пересечения хотя бы одного готового loss interval до dataThrough; otherwise INCIDENT_HAS_NO_LOSS_INTERVAL.
- (decision) Ongoing reason incident автоматически классифицирует последующие eligible loss intervals до close; from должен быть раньше current dataThrough.
- (decision) В один instant допускается максимум один state override и одна reason: state-effect overlaps конфликтуют между собой, reason-effect overlaps конфликтуют между собой, state-only и reason-only могут пересекаться.
- (decision) Несколько причин, primary/secondary и causal hierarchy вне MVP.
- (decision) Incident supports create/get/list/update/close/cancel; update cannot change id/machineId/author/createdAt and revalidates both overlap dimensions.
- (decision) DELETE soft-cancels through cancelledAt, is idempotent, removes both effects, remains readable with includeCancelled=true and cannot be restored in MVP.
- (decision) Author optional max 100 and untrusted without authentication; comment optional max 500.
- (decision) Mutation creates minute-aligned dirty union of old/new intervals and recalculates effective intervals, machine metrics and machine loss buckets without replay raw/calculated state.
- (decision) Effective projection stores separate stateIncidentId and reasonIncidentId plus lossReasonId; reason-only incident leaves stateSource CALCULATED.
- (constraint) No versions, full audit log, reason hierarchy, user-editable category catalog, future incident schedule or automatic reason detection in MVP.
- (event) Пользователь явно согласовал рекомендуемые boundary decisions; открытых вопросов внутри блока нет.
- (decision) IncidentEffectType is a closed derived Java/OpenAPI enum STATE_OVERRIDE/LOSS_ANNOTATION/STATE_OVERRIDE_WITH_REASON, stored nowhere.
- (decision) Future boundaries are not scheduled: from must be <=now, non-null to must be <=now; ongoing uses to=null.
- (decision) Existing incident may update boundaries/comment while retaining its disabled reason; assigning or switching to a disabled reason is forbidden.
- (event) Coherence validation passed: five capabilities have intent and testable success; enum/catalog boundary, independent overlap dimensions, ongoing attribution, soft cancel and dirty publication are internally consistent.
- (event) Preservation validation passed: all accepted recommendations for mutability, disabled reasons, dataThrough validation, single reason cardinality, lifecycle, author and enum usage are represented.
- (event) Spec finalized after explicit user acceptance; three companions exist, focused manual override contract is synchronized, git diff check passed, and no open questions remain inside this block.
- (decision) JWT authentication is required for API use, but ManualIncident author remains optional untrusted display input until identity-to-author mapping is designed; full audit remains out of MVP.
- (decision) New Enterprise starts with no predefined LossReason rows; user adds enterprise-specific reasons through ordinary API, while demo/test fixtures provision their own records outside migrations.
