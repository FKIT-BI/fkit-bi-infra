- (direction by user) Отдельный компактный spec-пакет должен фиксировать согласованный блок иерархии оборудования.
- (decision by user) Иерархия оборудования: Enterprise владеет ProductionLine, ProductionLine владеет Machine, Machine владеет деревом Component и каталогом TelemetrySignal.
- (decision by user) Shift принадлежит Enterprise, но не является узлом дерева оборудования.
- (decision by user) Sensor и Instrument моделируются значениями Component.kind, а не отдельными сущностями или таблицами.
- (decision by user) TelemetrySignal всегда принадлежит одной Machine и может дополнительно ссылаться на один Component той же Machine; отсутствие componentId означает сигнал уровня машины.
- (decision by user) Component всегда принадлежит одной Machine и может иметь не более одного parent Component той же Machine; вложенность конечна, циклы запрещены, жёсткий бизнес-лимит глубины не вводится.
- (decision by user) ProductionLine не переносится между Enterprise, Machine не переносится между ProductionLine, Component не переносится между Machine; parent Component можно изменить только внутри той же Machine.
- (decision by user) При изменении parent Component исторические данные отображаются через текущую структуру, поскольку версии конфигурации в MVP отсутствуют.
- (decision) Component.sortOrder задаёт представление среди siblings, допускает одинаковые значения и стабилизируется вторичной сортировкой по code.
- (decision by user) Каталог ComponentKind должен содержать расширенный набор наглядных типов для будущего использования и OTHER как совместимый fallback.
- (capability) CAP-1: Пользователь создаёт и читает однозначную иерархию Enterprise → ProductionLine → Machine с обязательным владельцем каждого узла.
- (capability) CAP-2: Пользователь описывает произвольную конечную структуру Machine единым деревом Component с явным ComponentKind.
- (capability) CAP-3: Пользователь привязывает TelemetrySignal к Machine целиком или к её конкретному Component без межмашинных ссылок.
- (capability) CAP-4: Пользователь корректирует дерево внутри Machine без смены владельца, циклов или потери идентичности сущностей.
- (constraint) MVP использует текущую структуру без истории версий и не поддерживает переносы между владельцами или физическое удаление узлов.
