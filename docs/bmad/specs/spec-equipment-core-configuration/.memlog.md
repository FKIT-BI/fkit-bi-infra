- (direction) Пользователь согласовал отдельный spec-пакет для базовой конфигурации Enterprise, ProductionLine и Machine.
- (decision) Enterprise содержит неизменяемые id и code, изменяемые name и timezone с ограничением, собственный status ACTIVE/DISABLED и технические createdAt/updatedAt.
- (decision) Одно развёртывание поддерживает несколько Enterprise; code глобально уникален, name может повторяться.
- (decision) Enterprise.timezone обязателен и использует IANA ZoneId; после появления телеметрии, инцидентов, запусков генератора или рассчитанной аналитики изменение timezone блокируется.
- (decision) Shift не встраивается в Enterprise и определяется отдельной сущностью и API.
- (decision) Код предлагает и формирует frontend; backend только проверяет формат и уникальность, сохраняет и запрещает изменение.
- (decision) ProductionLine содержит неизменяемые id, enterpriseId и code, изменяемые name и sortOrder, собственный status и технические timestamps.
- (decision) ProductionLine.code уникален внутри Enterprise; name и sortOrder могут повторяться, сортировка выполняется по sortOrder и затем code.
- (decision) Если sortOrder линии не передан, backend назначает max sortOrder плюс 10, начиная с 10; отдельная batch-reorder операция в MVP не нужна.
- (decision) ProductionLine не переносится между Enterprise и может существовать без Machines.
- (decision) DISABLED ProductionLine не изменяет статусы Machines и не удаляет историю; активный generator run продолжает расчёты по снимку, новый run через отключённую линию запрещён.
- (decision) Machine всегда принадлежит одному Enterprise напрямую, а lineId при создании может быть null или ссылаться на ProductionLine того же Enterprise.
- (decision) Machine.lineId допускает только однократный переход null к lineId; повторное назначение, перенос между Lines и снятие с Line в MVP запрещены.
- (decision) Machine можно создать сразу с lineId либо позднее назначить Line индивидуально или атомарной пакетной операцией.
- (decision) Пакетное назначение Machines одной Line работает all-or-nothing; наличие уже назначенной, неизвестной или принадлежащей другому Enterprise машины возвращает конфликт с деталями и не изменяет ни одну машину.
- (decision) Неназначенная Machine может редактироваться и получать Components, TelemetrySignals и правила, но не участвует в generator run, приёме производственной telemetry и аналитических расчётах.
- (decision) Machine содержит id, enterpriseId, nullable lineId, code, name, optional machineType, optional inventoryNo, optional парные nominalRate и productionUnit, nullable sortOrder, status, parameters и timestamps.
- (decision) machineType является свободной строкой только для отображения и фильтрации и не определяет аналитику, сигналы, компоненты или генератор.
- (decision) inventoryNo необязателен, изменяем и при наличии уникален внутри Enterprise.
- (decision) nominalRate должен быть положительным и задаётся только вместе с productionUnit; при отсутствии пары показатель performance равен null.
- (decision) До назначения Line Machine.sortOrder равен null; при назначении backend задаёт max sortOrder плюс 10, а пакет сохраняет порядок machineIds.
- (decision) Machine создаётся со status DISABLED по умолчанию и переводится в ACTIVE только после проверки полноты конфигурации; точная signal/rule validation дополняется соседними спецификациями.
- (decision) Machine update атомарно изменяет name, machineType, inventoryNo, nominalRate, productionUnit, sortOrder и parameters; id, enterpriseId, lineId, code и status обновляются только согласно отдельным правилам или командам.
- (decision) Components создаются отдельно внутри конкретной Machine, не существуют без Machine и не назначаются из общего пула; machineId компонента неизменяем.
- (decision) TelemetrySignals и аналитические правила настраиваются отдельно от Machine update; сигнал принадлежит Machine и опционально Component той же Machine.
- (capability) CAP-1: Пользователь создаёт и изменяет несколько Enterprise с однозначным кодом и часовым поясом, не разрушая временную интерпретацию существующих данных.
- (capability) CAP-2: Пользователь создаёт и упорядочивает ProductionLines внутри Enterprise и управляет их административным статусом без каскадного изменения Machines.
- (capability) CAP-3: Пользователь создаёт и атомарно изменяет Machine в Enterprise до полной готовности, включая производственные атрибуты и параметры.
- (capability) CAP-4: Пользователь назначает одну или несколько свободных Machines существующей Line того же Enterprise, а система предотвращает повторное или межвладельческое назначение.
- (capability) CAP-5: Пользователь независимо собирает конфигурацию Machine из Components, TelemetrySignals и правил и активирует её только после проверки готовности.
- (constraint) MVP не поддерживает физическое удаление, перенос или снятие Machine с Line, backend-генерацию code, отдельный каталог machineType и вложенное сохранение всей конфигурации одним Machine update.
