- (direction) Пользователь согласовал бизнес-классификацию RUN/IDLE/DOWN/SETUP/PLANNED_STOP/OFFLINE и её влияние на Availability, Performance и data coverage.
- (capability) CAP-1: Система однозначно классифицирует effective state duration; успех — каждый state имеет нормативный business meaning и единственный productive/operating/planned/data-gap class.
- (capability) CAP-2: Analytics формирует базовые additive durations для Availability и Performance; успех — RUN/IDLE/DOWN/SETUP/PLANNED_STOP раскладываются без double count, а OFFLINE не считается производственным простоем.
- (capability) CAP-3: Analytics отдельно сообщает telemetry coverage; успех — underlying calculated OFFLINE уменьшает dataCoverage даже под manual business override и остаётся видимым.
- (capability) CAP-4: Система выделяет failure/recovery события из state transitions; успех — вход в DOWN создаёт failure, выход в non-DOWN/non-OFFLINE создаёт recovery, OFFLINE сам не является failure.
- (capability) CAP-5: Rules могут выражать реальные производственные переходы без жёсткой transition matrix; успех — любое user state может перейти в другое, а OFFLINE управляется только system freshness policy.
- (decision) RUN is productive and operating time; IDLE is available non-producing operating time and performance loss.
- (decision) DOWN is unplanned stop and availability loss; SETUP is planned operational loss included in planned production time but excluded from operating time.
- (decision) PLANNED_STOP is visible classified time excluded from planned production/Availability denominator; OFFLINE is data gap, not downtime, failure or automatic loss reason.
- (decision) plannedProductionTime=RUN+IDLE+DOWN+SETUP; operatingTime=RUN+IDLE; productiveTime=RUN; availability=operatingTime/plannedProductionTime when denominator positive.
- (decision) IDLE lowers Performance rather than Availability; exact production/output formula is owned by metric spec.
- (decision) dataCoverage=(coveredDuration-underlyingOfflineDuration)/coveredDuration for positive coverage; manual override changes business state but not underlying offline duration.
- (constraint) State duration facts are stored additively; percentages are derived at query time and never averaged.
