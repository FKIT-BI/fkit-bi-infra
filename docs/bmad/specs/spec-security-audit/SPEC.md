# Безопасность и граница развёртывания MVP

## Why

FKIT BI предоставляет API конфигурации, управления генератором и аналитики во внешнем развёртывании. MVP должен аутентифицировать API-доступ и обеспечивать HTTPS без системы ролей и отдельного инфраструктурного стека.

## Capabilities

- **CAP-1**
  - **intent:** Frontend и сервисные клиенты используют защищённые Analytics и Generator API.
  - **success:** Все публичные операции требуют валидный JWT Bearer; запросы без токена и с невалидным токеном отклоняются, а все аутентифицированные пользователи имеют одинаковые права.
- **CAP-2**
  - **intent:** Оператор публикует приложение по HTTPS на `*.bi.kitexp.ru` с публичным или самоподписным сертификатом.
  - **success:** Nginx поддерживает оба режима сертификата, перенаправляет HTTP на HTTPS в TLS-развёртывании и перезагружается после обновления сертификата.
- **CAP-3**
  - **intent:** Базовая учётная запись добавляет пользователей через минимальную форму.
  - **success:** Первую базовую учётную запись создаёт оператор при развёртывании; только она может создавать последующие учётные записи, без введения ролей/RBAC.

## Constraints

- Роли/RBAC, OAuth, полный аудит и подтверждённая атрибуция `author` не входят в MVP.
- Сохраняются действующие требования least privilege для БД, разделения секретов, ограничений запросов и внутренней доступности observability.
- Wildcard-сертификат Let’s Encrypt требует DNS-01; самоподписный сертификат — отдельный режим доверия для разработки и демонстрации.
- DNS-провайдер выбран: Yandex Cloud DNS; автоматизация и секреты Certbot описаны в `security-and-deployment.md`.
- Основной host — `bi.kitexp.ru`; сертификат содержит и `bi.kitexp.ru`, и `*.bi.kitexp.ru`.
- Analytics выпускает общий JWT `HS256` (30 минут, без refresh token), Generator только проверяет его; bootstrap пользователь provisioned одноразово, обычные пользователи создаются им через auth API.
- Login и bootstrap-only создание пользователей описаны в отдельном OpenAPI v1.0.0 `fkit-bi-infra/docs/contracts/auth-api.yaml`.

## Non-goals

- Права на уровне предприятия или отдельных ресурсов.
- Полноценная система ролей, восстановления доступа, MFA и управления refresh-token/сессиями.
- Публичный доступ к Prometheus, Grafana, exporters или метрикам приложения.

## Success signal

Оба API-контракта объявляют JWT Bearer; неаутентифицированные запросы отклоняются, базовая учётная запись создаёт пользователей, аутентификация единообразна для Analytics и Generator; Nginx использует host ports 80/443 и не публикует observability endpoints.
