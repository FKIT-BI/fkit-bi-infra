- (capability) CAP-1: Frontend и сервисы используют JWT Bearer authentication; success — защищённые API принимают только валидный токен, роли и RBAC не вводятся.
- (capability) CAP-2: Оператор разворачивает HTTPS на *.bi.kitexp.ru с публичным Certbot сертификатом либо самоподписным сертификатом; success — Nginx обслуживает TLS в обоих режимах и автоматически перезагружается после обновления сертификата.
- (decision) JWT обязателен во всех публичных Analytics и Generator API; все аутентифицированные пользователи имеют одинаковые права, роли/RBAC, OAuth и сложный identity management не входят в MVP.
- (decision) Поле author остаётся необязательным непроверенным display value, не является подтверждением identity; полный аудит изменений конфигурации и incidents вне MVP.
- (decision) Nginx является внешней TLS/reverse-proxy границей; метрики и Grafana/Prometheus/exporters не публикуются наружу; секреты не коммитятся и разделяются по назначению.
- (decision) Wildcard *.bi.kitexp.ru через Let’s Encrypt требует DNS-01 challenge; Certbot выполняет выпуск/renewal DNS-плагином при наличии DNS API либо операторским способом; самоподписанный сертификат — отдельный режим для demo/dev.
- (constraint) Принятые ранее DB least-privilege users, limits и query safeguards остаются обязательными из SQL foundation, observability и API контрактов; не ослаблять при включении JWT.
- (question) Нужно выбрать минимальный источник учётных данных и bootstrap первой учётной записи/секрета JWT; user не утверждал env-only shared account или таблицу пользователей.
- (question) Для полностью автоматического wildcard renewal требуется выбрать DNS provider/plugin и способ безопасной выдачи узкоскорых DNS credentials; DNS provider не указан.
- (event) Первый проход coherence: API authentication и TLS modes зафиксированы; account bootstrap и DNS automation оставлены open, поскольку источник учетных данных и DNS provider не выбраны.
- (event) Pass 1 coherence passed: two capabilities include testable success, roles/RBAC and TLS modes are explicit, credential bootstrap and DNS provider remain open rather than assumed.
- (event) Pass 2 preservation passed: JWT requirement, no-roles scope, author/audit boundary, Nginx, wildcard DNS-01, self-signed mode, secret/network controls, and accepted DB/query controls are represented in SPEC, companion, API contracts or linked specs.
- (event) L03 artifact rendered in Russian; machine-readable Analytics and Generator OpenAPI parse successfully and declare root bearerAuth. Full OpenAPI lint was not run because Redocly CLI is unavailable in this environment.
- (decision) Управление пользователями входит в MVP: первая bootstrap/base account создаётся оператором при развёртывании и только она может создавать последующие учётные записи; роли/RBAC не вводятся.
- (decision) Публичная DNS-зона управляется Yandex Cloud DNS; wildcard Certbot предполагается автоматизировать DNS-01 через совместимый dns-yandexcloud plugin и отдельную минимально привилегированную service account, секреты пользователь не передаёт в чат.
- (decision) Для deployment ingress Nginx публикует host ports 80 и 443; analytics/generator (8080), web (80) и PostgreSQL (5432) доступны только внутри Compose network, не публикуются host ports.
- (question) Рекомендуется сертификат с SAN *.bi.kitexp.ru и bi.kitexp.ru; wildcard сам по себе не покрывает apex. Требуется подтвердить, будет ли корневой bi.kitexp.ru использоваться как web hostname.
- (event) Updated after approval: bootstrap account creates users; Yandex Cloud DNS selected; ingress ports documented. The only DNS naming decision retained is whether to serve apex bi.kitexp.ru alongside wildcard.
- (decision) Основной публичный hostname MVP — bi.kitexp.ru; сертификат должен включать SAN bi.kitexp.ru и *.bi.kitexp.ru, чтобы покрыть apex и будущие поддомены.
- (event) Hostname/SAN decision resolved: apex bi.kitexp.ru is primary and wildcard subdomains remain covered.
- (decision by analyst) Чтобы разблокировать проектирование MVP, приняты минимальные auth defaults: Analytics — общий issuer HS256 (secret 256-bit+ вне репозитория/БД), claims sub/iss/aud/iat/exp без roles, TTL 30 минут, без refresh token; frontend sessionStorage; BCrypt password hashes; bootstrap создаётся одноразовой командой при пустой users table; только immutable bootstrap marker разрешает POST users; username уникален case-insensitive.
- (decision by analyst) DNS credentials передаются только deploy-time secret с минимальным доступом к целевой зоне; Login публичен, остальные endpoints защищены Bearer; API transport и abuse limits будут оформлены отдельным Auth OpenAPI.
- (event by analyst) Coherence validation passed: Analytics owns issuance, Generator validates the shared token, secret/bootstrap credentials stay outside SQL migrations and images, and auth transport remains isolated from business API DTOs.
- (decision by analyst) Auth OpenAPI v1.0.0 is separate at fkit-bi-infra/docs/contracts/auth-api.yaml: login is public, user creation is bootstrap-only, JWT access TTL is 30 minutes with no refresh token, login limit is 10/minute/IP and bootstrap create limit is 5/minute.
- (event by analyst) Auth API OpenAPI self-validation passed YAML parsing and resolution of all 25 local references; API transport and deployment security defaults are aligned.
- (decision by analyst) Auth abuse guard defaults: login 10/minute per public client IP; bootstrap account user creation 5/minute; Nginx overwrites forwarded client IP header, invalid login response does not distinguish unknown username from bad password.
- (event by analyst) Auth OpenAPI lint passed with Redocly recommended rules and no warnings; v1.0.0 contract has 2 operations, all 25 local references resolve, and security-and-deployment plus TODO now link the contract.
- (decision by analyst) Nginx overwrites the forwarded client-IP header trusted by the login rate limiter; auth API documentation names this trust boundary.
