# Правила идентификации и изменяемости

## Области уникальности технических кодов

| Сущность | Область уникальности `code` |
| --- | --- |
| Enterprise | Вся система |
| Shift | Одно Enterprise |
| ProductionLine | Одно Enterprise |
| Machine | Одно Enterprise |
| Component | Одна Machine |
| TelemetrySignal | Одна Machine |
| LossReason | Одно Enterprise |

`code` стабилен после создания. Изменяемое отображаемое название хранится отдельно в `name`.

## Machine

| Поле или связь | Правило MVP |
| --- | --- |
| `id` | Неизменяемый UUID, генерируется backend |
| `code` | Неизменяемый технический код |
| `enterpriseId` | Обязательный неизменяемый владелец |
| `lineId` | Необязателен при создании; один раз изменяется из `null` в Line того же Enterprise, затем неизменяем |
| `inventoryNo` | Необязателен; при наличии уникален внутри Enterprise, допускает исправление и не используется как внешний ключ |
| `name` | Изменяемо |
| `machineType` | Необязательная изменяемая строка для отображения и фильтрации |
| `nominalRate`, `productionUnit` | Необязательная изменяемая пара; rate положителен и задаёт выпуск за час |
| `sortOrder` | `null` без Line; изменяемый порядок внутри назначенной Line |
| `status` | При создании `DISABLED`; переключается между `ACTIVE` и `DISABLED` после доменной проверки |
| `parameters` | Изменяемы при сохранении доменных инвариантов |
| `components` | Изменяемы внутри той же Machine |
| `signals` | Изменяемы при сохранении семантики уже записанных данных |
| `stateRules`, `thresholds` | Изменяемы; последствия для пересчёта определяются отдельным spec |

Код предлагает frontend, а backend только проверяет его формат, уникальность и неизменяемость. Машина без линии может конфигурироваться, но не участвует в новых generator runs, приёме производственной телеметрии и аналитических расчётах.

## Статус и операционное состояние

`status` задаётся пользователем и выражает административную доступность конфигурационной сущности:

- `ACTIVE` — сущность разрешена к использованию;
- `DISABLED` — сущность сохранена, но не должна использоваться в новых операциях.

Собственный `status` хранится у `Enterprise`, `Shift`, `ProductionLine`, `Machine`, `Component` и `TelemetrySignal`. `Sensor` и `Instrument` представлены значениями `Component.kind` и используют идентичность, код и статус компонента. Наследуемый `effectiveStatus` не вводится: система не хранит и не возвращает результат объединения статусов сущности и её предков.

Status-команда изменяет только целевую сущность и никогда не выполняет каскад. Dependency-specific validation может отклонить использование или изменение отключённого требуемого объекта либо сделать Machine неготовой к повторной активации, но не переписывает status связанных строк.

Для `Shift` статус управляет доступностью в новых operational-настройках и generator runs, но не отменяет историческую применимость в сохранённом validity-интервале. Историческое чтение и перерасчёт отключённой смены разрешены.

Операционное состояние Machine является отдельным результатом аналитики:

- `RUN`;
- `IDLE`;
- `DOWN`;
- `PLANNED_STOP`;
- `SETUP`;
- `OFFLINE`.

Вычисление операционного состояния не меняет `status` Machine. Операционное состояние:

- не является полем строки `Machine`;
- не записывается генератором в raw telemetry;
- сохраняется аналитикой как текущая проекция и как временные интервалы;
- для текущего представления читается из подготовленной проекции, для истории — из интервалов.

Точные SQL-имена таблиц, состав колонок, правила пересчёта и целостности определяются отдельной спецификацией хранения и расчёта телеметрии.

## Взаимодействие статуса с генератором

- При старте run генератор сохраняет самостоятельный снимок необходимой конфигурации.
- Изменение или отключение сущности после старта не изменяет снимок, не останавливает и не отменяет активный run.
- Новый run не запускается, если требуемая для снимка конфигурационная сущность имеет `DISABLED`.
- Транспортная ошибка, итоговый `RunStatus` и поведение запланированного, но ещё не начавшегося run определяются в спецификации генератора.
