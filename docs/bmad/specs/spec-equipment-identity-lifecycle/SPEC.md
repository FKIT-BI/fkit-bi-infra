> **Canonical contract.** Этот SPEC и файлы из `companions:` составляют полный контракт блока идентификации, статусов и принадлежности оборудования.

# Идентификация и жизненный цикл оборудования

## Why

Конфигурация оборудования должна оставаться однозначной для SQL-связей, API, правил, генерации и аналитической истории, даже когда пользователь меняет отображаемые свойства или отключает объект. MVP должен обеспечивать эту устойчивость без истории версий конфигурации, физического удаления и операций переноса.

## Capabilities

- **CAP-1**
  - **intent:** Система однозначно идентифицирует каждую конфигурационную сущность внутренним UUID и предоставляет стабильный читаемый технический код для конфигурации, правил, генератора, логов и будущих интеграций.
  - **success:** После изменения разрешённых отображаемых или расчётных параметров UUID и технический код сущности остаются прежними, а все существующие связи продолжают разрешаться.

- **CAP-2**
  - **intent:** Пользователь может включать и отключать конфигурационные сущности, не уничтожая связанные данные и аналитическую историю.
  - **success:** `Enterprise`, `Shift`, `ProductionLine`, `Machine`, `Component` и `TelemetrySignal` хранят собственный `ACTIVE` или `DISABLED`; переключение статуса не удаляет сущность, телеметрию, интервалы, агрегаты или исторические ссылки, а уже активный generator run продолжает работу по своему снимку.

- **CAP-3**
  - **intent:** Система независимо представляет административную доступность машины и её вычисляемое операционное состояние.
  - **success:** Машина сохраняет только конфигурационный статус `ACTIVE` или `DISABLED`, а аналитика отдельно сохраняет текущую проекцию и временные интервалы `RUN`, `IDLE`, `DOWN`, `PLANNED_STOP`, `SETUP`, `OFFLINE`, рассчитанные из телеметрии без изменения конфигурационного статуса.

- **CAP-4**
  - **intent:** MVP сохраняет неизменяемую принадлежность машины предприятию и компонентов машине, допуская однократное назначение свободной машины линии.
  - **success:** `enterpriseId` машины и `machineId` компонента не меняются; `lineId` машины допускает только переход из `null` в линию того же предприятия, после чего API отклоняет перенос или снятие назначения.

## Constraints

- `id` — генерируемый backend неизменяемый UUID, используемый для SQL-связей и API-адресации.
- `code` — отдельный от `id` неизменяемый читаемый технический идентификатор; области уникальности определены в `entity-rules.md`.
- Конфигурационные сущности используют только `ACTIVE` и `DISABLED`.
- `effectiveStatus` не вводится, не хранится, не вычисляется и не возвращается API; каждая сущность предоставляет только собственный `status`.
- Status-команда не каскадирует изменения на потомков; dependency validation влияет на допустимость использования, readiness или нового generator run, а не переписывает связанные статусы.
- Операционное состояние вычисляется из телеметрии только для машины; компоненты, включая виды `SENSOR` и `INSTRUMENT`, не получают отдельного вычисляемого состояния в MVP.
- Операционное состояние не хранится в строке `Machine` и не записывается в raw telemetry; подготовленные результаты принадлежат аналитической проекции.
- Активный generator run не останавливается при последующем отключении участвующей сущности и продолжает работу по снимку конфигурации, зафиксированному при запуске.
- Новый generator run не запускается, если необходимая ему конфигурационная сущность имеет `DISABLED`; точные ошибка и `RunStatus` принадлежат отдельной спецификации генератора.
- Отключённая `Shift` недоступна для новых operational-настроек и generator runs, но остаётся доступной для исторического чтения и перерасчёта внутри своего validity-интервала.
- Пользовательский API не выполняет физическое удаление конфигурационных сущностей.
- Машина всегда принадлежит предприятию; её `lineId` может быть пустым до первого назначения линии того же предприятия, после чего не изменяется.
- Машина создаётся в `DISABLED` и активируется только после проверки готовности конфигурации.
- Машина не переносится между линиями и не снимается с линии, а компоненты любого вида не переносятся между машинами.
- `Sensor` и `Instrument` не являются отдельными конфигурационными сущностями: они представлены значениями `Component.kind`.
- Изменяемость полей Machine ограничена правилами из `entity-rules.md`.

## Non-goals

- Перенос существующей машины между производственными линиями.
- Перенос компонента любого вида между машинами.
- Отдельные таблицы и API-сущности `Sensor` и `Instrument`.
- Физическое удаление конфигурационных сущностей через пользовательский API.
- Отдельное вычисляемое состояние здоровья компонентов и датчиков.
- Наследуемый или вычисляемый `effectiveStatus` конфигурационных сущностей.
- История версий конфигурации оборудования.

## Success signal

Пользователь создаёт оборудование со стабильными кодами, подготавливает отключённую машину без линии, однократно назначает её линии своего предприятия, изменяет разрешённые параметры и отключает объекты без потери связей или истории; backend отклоняет повторное назначение, переносы, запрещённые удаления и новые запуски генератора с отключёнными сущностями, не прерывая уже активный запуск.
