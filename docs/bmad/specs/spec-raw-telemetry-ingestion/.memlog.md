topic: Сырая телеметрия, пакетная запись и доступность ingestion

- (direction) Пользователь установил приоритет: доступность сервиса важнее полноты raw telemetry и немедленной согласованности; ограниченная потеря сырой телеметрии допустима.
- (capability) CAP-1: Generator передаёт типизированные raw-измерения атомарными пакетами; успех — принятый пакет целиком сохранён как batch header и append-only rows либо целиком отклонён.
- (capability) CAP-2: Повторная доставка пакета не размножает данные; успех — producerId и producerBatchId образуют ключ идемпотентности без UUID и уникального индекса на каждое измерение.
- (capability) CAP-3: Analytics обрабатывает realtime, late, out-of-order и historical данные по observedAt; успех — event time сохранён, future realtime сверх допуска отклонён, а scheduled run не записывает значения заранее.
- (capability) CAP-4: Источник и backend сохраняют диагностируемое качество без потери аномальных значений; успех — типовые ошибки отклоняются, а BAD, UNCERTAIN и out-of-range факты остаются raw с компактными flags.
- (capability) CAP-5: Realtime ingestion деградирует без остановки сервиса; успех — ограниченные очередь, ожидание и retry завершаются сбросом пакета с наблюдаемыми счётчиками, а не бесконечной блокировкой.
- (capability) CAP-6: Frontend читает последнюю готовую аналитику независимо от raw-записи и фонового расчёта; успех — query API не ждёт ingestion/recalculation и возвращает freshness metadata.
- (decision) Физическая модель MVP: ingest batch header плюс типизированные measurement rows; JSONB и frame payload не используются как основное хранение.
- (decision) Measurement хранит signalId, observedAt, ordinal, одну из valueDouble/valueLong/valueBoolean/valueText, sourceQuality и validationFlags; receivedAt нормализован в batch header.
- (decision) Batch хранит monotonic id, producerId, producerBatchId, producerSequence, nullable generatorRunId, mode, receivedAt, count и min/max observedAt.
- (decision) Пакет до 1000 measurements записывается одной короткой транзакцией; partial success внутри пакета отсутствует.
- (decision) Raw quality использует GOOD, UNCERTAIN, BAD и compact validation flags OUT_OF_RANGE, SOURCE_UNCERTAIN, SOURCE_BAD, CLOCK_SKEW; null, NaN, infinity и несовместимый тип отклоняются.
- (decision) Realtime future skew по умолчанию ограничен 5 секундами; past/late и historical данные принимаются, future scheduled telemetry заранее не сохраняется.
- (decision) Raw partitioned by observedAt на суточные партиции, создаваемые до ingestion; raw не хранит shiftId, state или calculated metrics.
- (decision) Горячая raw-таблица не имеет FK на TelemetrySignal, per-measurement unique key, value indexes или UPSERT; основной read index — signalId plus observedAt.
- (decision) Realtime writer использует bounded buffer и короткий retry, при перегрузке отбрасывает старейшие незаписанные пакеты; historical writer throttles/pauses/fails без захвата realtime ресурсов.
- (decision) Query, ingestion и worker workloads получают раздельные connection budgets; frontend читает projections и не ждёт перерасчёта.
- (decision) Потери наблюдаемы через generated/accepted/rejected/dropped counts, failed batches, producer sequence gaps и lastSuccessfulWriteAt.
- (constraint) Best-effort и допустимая потеря применяются только к raw telemetry; equipment configuration, rules, incidents и generator definitions остаются durable transactional data.
- (constraint) Raw retention duration остаётся отдельным решением нагрузочного профиля; удаление выполняется целыми partitions и не входит в ingestion transaction.
- (decision) receivedAt назначает PostgreSQL; producerSequence диагностически возрастает внутри producer stream, которым для generator является run.
- (event) Coherence validation passed: six capabilities have intent and testable success; availability priority, atomicity, best-effort loss and durable-data exception are consistent.
- (event) Preservation validation passed: accepted measurement fields, batch idempotency, quality, event-time modes, SQL hot path, resource isolation, observable loss and frontend read behavior are present; retention duration is explicitly delegated.
- (event) Spec finalized after user acceptance; no open question remains inside this block, while retention remains owned by E13/A04.
- (decision) A04/E13 resolved raw retention at 90 days; expired UTC-day partitions are removed only after dependent dirty windows are closed and published aggregates exist.
- (decision) Minimal-host budgets resolve analytics connections at 14–16 and generator connections at 2–3 while preserving query capacity from ingestion/calculation concurrency.
- (constraint) After a raw partition is deleted, full recalculation of that time range is unavailable, while already published intervals, rollups and incidents remain readable.
- (event) Coherence validation passed after retention update: 90-day cleanup is consistent with partitioning, dirty windows and non-blocking ingestion.
- (event) Preservation validation passed after retention update: A04/E13 duration, prerequisites, recalculation consequence and connection budgets are linked into the derived contract.
- (event) Post-render validation passed: derived SPEC, storage and availability companions now consistently reference 90-day retention and minimal-host connection budgets.
- (direction) Пользователь после архитектурной проверки принял упрощённый MVP-вариант исправлений без отдельных maintenance services и нескольких datasource pools.
- (decision) ingest_batch stores canonical SHA-256 payload_hash; same producer key with equal hash is idempotent success, different hash is BATCH_ID_REUSED_WITH_DIFFERENT_PAYLOAD.
- (decision) Physical codes are fixed: mode 1 REALTIME/2 HISTORICAL; sourceQuality 0 GOOD/1 UNCERTAIN/2 BAD; validation flags 1 OUT_OF_RANGE and 2 CLOCK_SKEW; quality is not duplicated in flags.
- (decision) producerId and producerBatchId are bounded to 128 characters, raw string value to 500 characters, and all raw timestamps use TIMESTAMPTZ(3).
- (decision) telemetry.signal_usage durably stores firstObservedAt per Signal outside raw retention; first use and semantic mutation serialize through one documented lock protocol.
- (decision) The raw transaction also writes durable per-machine telemetry.recalculation_hint rows covering affected event-time ranges; Analytics later coalesces them idempotently into dirty work.
- (decision) Historical observedAt must be within the active 90-day raw window determined from PostgreSQL time; arbitrary older partitions are outside MVP.
- (decision) Partition routines are owner-owned SECURITY DEFINER with fixed search_path, validated dates, one topology advisory lock and short timeouts; ordinary detach retries later on lock miss, DETACH CONCURRENTLY is deferred.
- (decision) ingest_batch is non-partitioned in MVP and cleaned in bounded chunks after both its idempotency horizon and related raw retention expire; cleanup has an indexed predicate and vacuum/dead-tuple monitoring.
- (decision) Analytics keeps one Hikari pool; background workload semaphores ensure workers cannot consume all 14–16 connections, avoiding multi-pool complexity.
- (event) Coherence validation passed after architecture corrections: idempotency, first-use durability, raw-to-dirty handoff, retention and partition ownership form one executable MVP protocol.
- (event) Preservation validation passed after architecture corrections: all accepted reviewer-gate changes are represented without changing the availability-first policy.
- (decision by user) Writer использует shared transaction advisory lock по каждому distinct signal_id, semantic update — exclusive lock; collision производного 64-bit ключа допустим только как лишняя сериализация.
- (decision by user) Добавляется raw_partition_registry(day,status); raw/hint/recalculation creation берут shared row lock ACTIVE, retention переводит день в RETIRING под exclusive row lock перед финальной проверкой и detach.
- (decision by user) payload_hash считается по exact TELEMETRY_BATCH_V1 binary encoding; cleanup ingest_batch использует индекс (max_observed_at,id).
