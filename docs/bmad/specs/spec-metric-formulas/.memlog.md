- (direction) Пользователь полностью согласовал минимальный каталог формул для demo MVP и потребовал избегать лишней сложности.
- (capability) CAP-1: Analytics однозначно вычисляет time metrics; успех — states раскладываются в covered, planned production, operating и productive time без double count.
- (capability) CAP-2: Analytics вычисляет выпуск, Performance, Quality и OEE из raw additive facts; успех — формулы имеют единицы, null semantics и не требуют сохранения процентов.
- (capability) CAP-3: Analytics различает stops, failures и recoveries и вычисляет простые MTBF/MTTR; успех — один state timeline детерминированно даёт все event counts и reliability metrics.
- (capability) CAP-4: Analytics агрегирует показатели machine → line → enterprise без усреднения percentages; успех — сначала суммируются совместимые numerators/denominators, затем вычисляются ratios.
- (capability) CAP-5: Summary сравнивает текущий и предыдущий сопоставимый период; успех — обычный период сдвигается на равную duration, а shift occurrence сравнивается с предыдущим occurrence той же Shift.
- (decision) coveredTime=sum всех effective state durations; plannedProductionTime=RUN+IDLE+DOWN+SETUP; operatingTime=RUN+IDLE; productiveTime=RUN.
- (decision) Availability=operatingTime/plannedProductionTime; PLANNED_STOP и OFFLINE исключены из denominator, SETUP включён, IDLE считается доступной работой.
- (decision) PRODUCTION_COUNT означает все завершённые изделия, включая брак; output=sum production delta, scrap=sum scrap delta, goodOutput=output-scrap.
- (decision) IdealOutput=nominalRatePerHour*operatingTimeHours; Performance=output/idealOutput, поэтому IDLE снижает Performance.
- (decision) Performance не ограничивается сверху 100%, чтобы не скрывать неверный nominalRate или аномалию счётчика.
- (decision) Quality=(output-scrap)/output; OEE=Availability*Performance*Quality; показатели вычисляются при чтении и не сохраняются.
- (decision) При output=0 Quality=null; без SCRAP_COUNT Quality=null; при scrap>output Quality и OEE null с diagnostic warning.
- (decision) Если любой компонент OEE null, OEE=null.
- (decision) stopCount считает переходы RUN→IDLE и RUN→DOWN; failureCount считает входы в DOWN из состояния кроме DOWN/OFFLINE; recoveryCount считает выходы DOWN→non-DOWN/non-OFFLINE.
- (decision) MTBF=operatingTime/failureCount; MTTR=downTime/failureCount; при failureCount=0 оба показателя null.
- (decision) DataCoverage=(coveredTime-underlyingOfflineTime)/coveredTime; при coveredTime=0 null; coverage не переписывает бизнес-метрики автоматически.
- (constraint) Line/enterprise сначала суммируют machine-time, outputs, ideal outputs и event counts, затем вычисляют ratios; усреднение machine percentages запрещено.
- (decision) Line/enterprise output, Performance, Quality и OEE доступны только когда участвующие machines имеют одну productionUnit и необходимые данные; иначе эти показатели null.
- (decision) Для обычного периода previous=[from-duration,from); для shiftId+shiftDate previous — предыдущее calendar occurrence той же Shift; оба ограничиваются собственными closed minutes/dataThrough.
- (constraint) Любой ratio с нулевым, отрицательным или отсутствующим denominator возвращает null; отсутствующие исходные данные не подменяются нулём.
- (decision) Draft API корректируется: calendarSec заменяется coveredSec, IDLE отделяется от unplanned, SETUP отделяется от PLANNED_STOP, добавляются coverage/failures/scrap/Quality/OEE и новые формулы Availability/Performance.
