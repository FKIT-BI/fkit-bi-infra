---
topic: Выполнение realtime, historical и scheduled GenerationRun
updated: 2026-10-09T00:08
---

- (direction) Пользователь полностью принял предложенную семантику realtime, historical, scheduled, progress, checkpoint, stop, retry и idempotency.
- (capability) CAP-1: Realtime run следует wall clock без catch-up burst; успех — missed ticks пропускаются и учитываются, а observedAt не создаётся заранее.
- (capability) CAP-2: Historical run воспроизводимо генерирует прошлый [from,to); успех — range до 90 days выполняется virtual clock с throttling 1000–2000 measurements/s и deterministic phases.
- (capability) CAP-3: Scheduled run стартует в будущем как realtime; успех — timestamp с offset нормализуется UTC, до старта raw отсутствует, readiness повторно проверяется, misfire >30 s даёт SCHEDULE_MISSED.
- (capability) CAP-4: Пользователь видит сопоставимый progress любого mode; успех — common timestamps, phase/cycle, generatedThrough, nullable progressPercent, counters, last write and failure доступны в run detail.
- (capability) CAP-5: Historical execution восстанавливается без двойных measurements; успех — 5-minute chunks checkpointed only after confirmed batches, retry repeats deterministic batch IDs and resumes same run.
- (capability) CAP-6: Пользователь безопасно останавливает run; успех — stop idempotent, scheduled/queued cancel, running transitions through STOP_REQUESTED, current/flush batch bounded and leftovers counted dropped.
- (capability) CAP-7: HTTP retries не создают duplicate run; успех — required Idempotency-Key returns same run for same body and 409 IDEMPOTENCY_KEY_REUSED for changed body.
- (capability) CAP-8: Frontend переходит к готовой аналитике без ложной синхронизации; успех — COMPLETED означает raw generation complete, run exposes analytics context, а UI отдельно проверяет Analytics dataThrough/stale/recalculating.
- (decision) Realtime uses UTC server wall clock; ONCE ends after one phase sequence, LOOP continues to eventTo or stop, unbounded progressPercent is null.
- (decision) Realtime scheduler skips overdue ticks instead of generating a catch-up burst; skipped work is observable.
- (decision) Historical request requires UTC [from,to), from<to, to<=now and duration<=90 days; ONCE may complete before to, LOOP fills range.
- (decision) Historical range uses 5-minute event-time chunks and telemetry batches <=1000; checkpoint advances only after all batches of chunk are confirmed.
- (decision) New historical run overlapping previously generated coverage for the same machine is rejected; continuation starts at prior checkpoint to avoid double raw.
- (decision) Scheduled start accepts offset timestamp, stores UTC and uses Enterprise timezone only for UI; raw is absent before start and scheduled snapshot is not rebuilt.
- (decision) Scheduled misfire <=30 seconds starts immediately without backfill; larger delay fails with SCHEDULE_MISSED; pre-start stop produces CANCELLED.
- (decision) Progress percent derives from event-time coverage for bounded runs, not row count; unbounded realtime and pre-start scheduled expose null.
- (decision) Run detail exposes status/mode/attempt, temporal bounds, phase/cycle, generatedThrough, progress, generated/written/dropped/failed counters, lastSuccessfulWriteAt, stopRequestedAt and bounded failure.
- (decision) Stop completes or rolls back current transaction, attempts one bounded buffer flush, drops remainder on timeout and never waits indefinitely for PostgreSQL.
- (decision) Retry allowed only for FAILED with retryable=true; same runId/snapshot/seed/producer stream is reused, attemptNo increments and attempt history is durable.
- (decision) Historical retry resumes checkpoint and repeats current chunk idempotently; realtime retry continues from current wall time without filling gap; non-retryable validation/misfire requires new run.
- (decision) Run creation requires persistent Idempotency-Key; same key/body returns same response, key with different body returns 409 IDEMPOTENCY_KEY_REUSED.
- (decision) Frontend polls active run around every 2 seconds and scheduled/terminal list around every 10 seconds; SSE/WebSocket are outside MVP.
- (constraint) Generation completion never waits for analytics calculation; Generator does not call Analytics synchronously and does not claim analyticsReady.
- (event) User accepted the complete run execution block with no remaining decision gap.
- (event) Coherence validation passed: eight capabilities cover three clocks, progress, checkpoint, stop, retry, HTTP idempotency and Analytics handoff with measurable outcomes.
- (event) Preservation validation passed: accepted ranges, rates, chunk size, misfire, overlap, counters, terminal meanings, polling and recovery rules appear in SPEC or companions.
- (event) Spec finalized after user acceptance; no open question remains in run execution semantics.
- (decision) Historical from must be no earlier than PostgreSQL current time minus the active 90-day raw window; validation uses the database clock and to remains no later than acceptedAt.
- (decision) Historical readiness requires all UTC-day raw partitions intersecting the requested range to be attached and indexed before execution.
- (event) Coherence validation passed after aligning Historical admission with raw retention; existing duration, checkpoint and overlap rules remain unchanged.
- (event) Preservation validation passed: the run contract cannot create raw that is immediately eligible for retention.
