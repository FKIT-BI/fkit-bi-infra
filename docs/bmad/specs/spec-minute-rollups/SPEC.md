# Минутные агрегаты MVP

## Why

Frontend должен быстро читать готовую аналитику, пока realtime и historical telemetry продолжают записываться без блокировки тяжёлыми запросами. Для demo MVP достаточно одного минутного уровня numeric, machine и loss projections, который можно безопасно пересчитать после late data.

## Capabilities

- **CAP-1**
  - **intent:** Analytics может подготовить минутный ряд числового сигнала без чтения всех raw-измерений пользовательским запросом.
  - **success:** Закрытая UTC-минута отдаёт количества, качество, min/max/sum и первое/последнее usable-значение; average однозначно выводится из сохранённых фактов.

- **CAP-2**
  - **intent:** Analytics может получить выпуск и другие приращения из накопительных счётчиков.
  - **success:** Минутный `delta` учитывает последнее usable-значение до начала минуты, а распознанный сброс не создаёт отрицательное приращение.

- **CAP-3**
  - **intent:** Analytics может хранить аддитивные минутные факты машины.
  - **success:** Длительности состояний, выпуск, брак и количества переходов суммируются для произвольного периода, смены, линии и предприятия без усреднения готовых процентов.

- **CAP-4**
  - **intent:** Analytics может актуализировать агрегаты после realtime, late и historical telemetry.
  - **success:** Повторный расчёт полностью заменяет затронутые минутные строки и при одинаковом входе даёт тот же результат без частично опубликованных данных.

- **CAP-5**
  - **intent:** Query API может читать длительные периоды и разные equipment scopes из одного уровня агрегатов.
  - **success:** Machine buckets суммируются для line/enterprise, фильтруются по `shiftId + shiftDate`, а ответ сообщает согласованный `dataThrough` без отдельных `1h` и `1d` таблиц.

- **CAP-6**
  - **intent:** Analytics может подготовить минутные потери по состоянию и назначенной причине.
  - **success:** Loss timeseries и Pareto читают `machine_loss_bucket_1m` без тяжёлого соединения точных intervals для каждого пользовательского запроса.

## Constraints

- Нормативные поля трёх проекций описаны в `rollup-model.md`.
- Границы, расчёт COUNTER, состояния и повторная публикация описаны в `calculation-rules.md`.
- Единственный физический размер бакета MVP — одна минута.
- Бакет является полуоткрытым UTC-интервалом; публикуются только закрытые минуты.
- Проценты, коэффициенты и averages не хранятся: они вычисляются из аддитивных фактов.
- Пользовательские запросы не агрегируют большие raw-диапазоны.
- Повторный расчёт заменяет полный bucket и не использует накопительное `+=`.

## Non-goals

- Физические `1h`, `1d`, line и enterprise rollup-таблицы.
- Универсальная интервальная проекция для `STATE`-сигналов.
- Предрассчитанные Availability, Performance, OEE и другие ratios.
- Полный каталог причин и пользовательский поток назначения причины.
- Автоматический выбор нескольких уровней rollup.

## Success signal

Dashboard и исторический API читают закрытые минуты из трёх подготовленных проекций, запись raw telemetry при этом не выполняет расчёты синхронно, а late data можно повторно обработать полной идемпотентной заменой затронутых минут.
