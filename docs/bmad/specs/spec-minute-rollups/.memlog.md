---
topic: Минутные агрегаты телеметрии и машин для demo MVP
updated: 2026-10-10T17:46
---

- (direction) Пользователь согласовал минимальный rollup-контур и отдельно потребовал не усложнять demo MVP.
- (capability) CAP-1: Analytics формирует минутные агрегаты числовых сигналов; успех — закрытая UTC-минута отдаёт count/min/max/sum/first/last и данные о качестве без чтения всего raw-диапазона.
- (capability) CAP-2: Analytics корректно агрегирует накопительные COUNTER-сигналы; успех — минутный delta учитывает значение до начала минуты и не становится отрицательным при распознанном сбросе.
- (capability) CAP-3: Analytics хранит аддитивные минутные факты машины; успех — длительности состояний, выпуск, брак и переходы суммируются для любого периода и scope.
- (capability) CAP-4: Запоздавшие и исторические данные безопасно актуализируют агрегаты; успех — затронутые минуты полностью пересчитываются во временное представление и атомарно заменяют прежний результат.
- (capability) CAP-5: Query API строит line/enterprise и длительные периоды из минутных фактов; успех — результат получает shiftId/shiftDate и dataThrough без отдельных часовых или scope-таблиц.
- (decision) В MVP физически хранятся только два вида минутных проекций: signal_numeric_rollup_1m и machine_metric_bucket_1m.
- (decision) Единственный физический размер бакета MVP — 1 минута; 1h/1d добавляются только после измеренной необходимости.
- (decision) Бакет — полуоткрытый UTC-интервал [bucketStart,bucketStart+1m); сохраняются только полностью закрытые минуты.
- (decision) Неполная текущая минута не попадает в rollup; current API использует текущие проекции, а исторический ответ ограничивается dataThrough.
- (decision) GAUGE rollup хранит sampleCount, good/uncertain/bad counts, min/max/sum и первое/последнее usable значение с observedAt; average вычисляется как sum/usableCount.
- (decision) Если в минуте есть принятые samples, но нет usable values, строка сохраняет только counts и null numeric aggregates; если samples нет, строка отсутствует.
- (decision) COUNTER delta считается по последовательности usable значений с carry-in — последним usable значением до начала минуты; отрицательное изменение в MVP означает reset, увеличивает resetCount и добавляет текущее значение к delta.
- (decision) STATE/BOOLEAN сигналы не получают отдельную интервальную или rollup-таблицу в MVP: current читается из signal_current_value, короткая диагностика — из raw, а состояние машины — из machine state intervals.
- (decision) Machine bucket хранит covered/run/idle/down/setup/plannedStop/effectiveOffline/underlyingOffline duration, producedQuantity, scrapQuantity, failureCount, recoveryCount, shiftId, shiftDate и calculatedAt.
- (constraint) Business state durations внутри полностью покрытой минуты не пересекаются и суммарно равны coveredDuration; underlyingOfflineDuration является отдельной ортогональной data-quality величиной.
- (decision) Точные state transitions разрезаются по границе минуты; длительности хранятся в миллисекундах.
- (decision) shiftId и shiftDate определяются календарём предприятия для bucketStart и сохраняются в machine bucket; границы смены в MVP выровнены по минуте.
- (decision) Line и enterprise вычисляются суммированием machine buckets по текущей неизменяемой принадлежности машины; исторический перенос машин между линиями в MVP отсутствует.
- (constraint) Проценты, коэффициенты, average, Availability, Performance и OEE не сохраняются: API вычисляет их из аддитивных числителей и знаменателей.
- (constraint) Пересчёт не использует += и не изменяет опубликованный бакет по частям; публикуется полная замена результата для ключа бакета.
- (decision) Уникальные ключи проекций: (signalId,bucketStart) и (machineId,bucketStart); повторный расчёт одного входа даёт тот же результат.
- (event) Пользователь явно согласовал все решения блока в упрощённом варианте для demo MVP; открытых вопросов внутри блока нет.
- (decision) Numeric rollup отдельно хранит usableCount, поскольку quality=GOOD само по себе не заменяет проверку disqualifying validation flags.
- (decision) При одинаковом observedAt порядок raw измерений определяется существующей парой ingestBatchId + ordinal; отдельный measurementId не вводится.
- (event) Coherence validation passed: пять capabilities имеют intent и проверяемый success; один минутный уровень, две проекции, closed-minute semantics и идемпотентная публикация не противоречат соседним спецификациям.
- (event) Preservation validation passed: все согласованные решения по GAUGE, COUNTER reset/carry-in, machine durations, shift attribution, line/enterprise aggregation, dataThrough и отказу от 1h/1d сохранены; machine loss явно вынесен за границы.
- (event) Spec finalized after explicit user acceptance; companions существуют, capability IDs уникальны, git diff check пройден, открытых вопросов внутри блока нет.
- (decision) Machine metric bucket дополнительно хранит stopCount для согласованной метрики переходов RUN→IDLE или RUN→DOWN.
- (event) Minute rollup spec re-derived with stopCount in machine bucket and RUN→IDLE/DOWN calculation rule; coherence with metric formulas validated.
- (direction) Позднейшее требование пользователя: demo MVP должен быть функциональным, чрезмерное упрощение недопустимо при сохранении простой реализации.
- (decision) Предыдущее решение о двух физических projections уточнено: добавляется третья простая projection machine_loss_bucket_1m для быстрого loss timeseries и Pareto без query-time interval joins.
- (capability) CAP-6: Analytics подготавливает минутные потери по state и nullable reason; успех — loss timeseries и Pareto читают machine_loss_bucket_1m без тяжёлого query-time соединения точных intervals.
- (event) Minute rollup spec re-derived to six capabilities and three projections; machine_loss_bucket_1m supersedes the earlier two-projection simplification while retaining one physical 1m level and one dirty-window pipeline.
- (decision by user) signal_numeric_rollup_1m хранит отдельный outOfRangeCount наряду со счётчиками sourceQuality; OUT_OF_RANGE является validation flag, а не quality category.
- (event by analyst) Rollup companion updated and validated: signal numeric rollup has outOfRangeCount as a diagnostic count separate from source-quality categories.
