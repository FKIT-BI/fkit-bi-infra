# FKIT BI — архитектура демонстрационной версии

Согласованная основа MVP: веб-клиент, отдельные Spring-приложения Analytics и Generator, одна общая PostgreSQL и обязательные Prometheus/Grafana с exporters. Внутри каждого приложения функциональность разделяется на модули; это не набор микросервисов. Генератор пакетно добавляет raw measurements через JDBC-контракт. Analytics непрерывно обновляет read projections фоновыми workers, а HTTP синхронно читает последнюю committed проекцию. Создание инцидентов в MVP ручное; автоматическая классификация инцидентов, ETL и внешняя шина отложены. Канонические модели и контракты находятся в `docs/bmad/specs/` и `docs/contracts/`.

## Компоненты системы

Вложенные блоки — модули соответствующего приложения, а не отдельные микросервисы. Четыре области хранения находятся в одной PostgreSQL. Стрелки к базе обозначают выполняемые запросы. Пунктир обозначает будущую интеграцию.

| Область | Ответственность |
| --- | --- |
| Структура оборудования | Предприятие владеет линиями и станками; свободный станок можно однократно назначить линии. Станок владеет деревом компонентов, где датчики, приборы и инструменты являются видами компонента; сигнал принадлежит станку и может ссылаться на его компонент. CRUD выполняет основной backend. |
| Телеметрия | Генератор добавляет исходные измерения сигналов. Backend читает их и не изменяет при расчётах. |
| Аналитика | Текущее состояние, скорость, активность, всплески, аварийные показатели, интервалы простоя и исторические агрегаты. Расчёты выполняет backend. |
| Инциденты | Созданные сотрудниками ручные инциденты/причины и их lifecycle. Автоматическое обнаружение/классификация инцидентов не входит в MVP; ручные сведения хранятся отдельно от исходных измерений. |
| Генерация | Отдельный раздел web-клиента управляет сценариями и запусками через API генератора. |

## Общая последовательность всех пользовательских сценариев

Ветви `alt` обозначают разные действия пользователя. Генерация и фоновая аналитика работают независимо. Детальные последовательности приведены ниже.

```mermaid
sequenceDiagram
    actor U as Сотрудник
    participant W as Web-клиент
    participant B as Сервис аналитики
    participant G as Spring-генератор
    participant D as PostgreSQL

    alt Структура оборудования и настройки
        U->>W: Просмотреть, создать, изменить или отключить объект
        W->>B: CRUD предприятия, линии, станка, компонента, сигнала или настройки
        B->>B: Проверить данные и связи
        B->>D: Прочитать или изменить структуру
        D-->>B: Результат
        B-->>W: Структура или ошибка проверки
        W-->>U: Обновить интерфейс
    else Текущее состояние
        U->>W: Выбрать оборудование
        loop Пока открыт мониторинг
            W->>B: Запросить текущие показатели
            B->>D: SELECT последних current projections и их currency
            D-->>B: Значения, состояния и временные метки
            B-->>W: Скорость, активность, аварийные показатели и актуальность
            W-->>U: Обновить мониторинг
        end
    else Историческая аналитика
        U->>W: Выбрать оборудование, период и показатели
        W->>B: Запросить историю
        B->>D: SELECT агрегатов и инцидентов
        D-->>B: Доступные результаты
        opt Нужен пересчёт
            B-->>W: Идентификатор фоновой задачи
            B->>D: SELECT исходных измерений
            D-->>B: Измерения за период
            B->>B: Рассчитать показатели
            B->>D: Сохранить агрегаты
            W->>B: Запросить готовность результата
        end
        B-->>W: Простои, всплески активности, аварии и скорость
        W-->>U: Показать графики и временную линию
    else Сведения об инциденте
        U->>W: Открыть инцидент или зарегистрировать новый
        W->>B: Запросить существующие сведения при наличии
        B->>D: SELECT инцидента
        D-->>B: Сведения об инциденте
        B-->>W: Карточка или форма нового инцидента
        U->>W: Внести время, причину, комментарий и действия
        W->>B: Сохранить ручные сведения
        B->>D: Записать инцидент и сведения сотрудника
        D-->>B: Сохранено
        B-->>W: Обновлённый инцидент
    else Управление генерацией
        U->>W: На странице генерации настроить сценарий
        W->>G: Передать настройки сценария
        G->>D: SELECT конфигурации оборудования
        D-->>G: Конфигурация
        G-->>W: Сценарий принят или ошибки
        U->>W: Запустить сценарий
        W->>G: Создать запуск
        G-->>W: Идентификатор запуска
        par Генерация в фоне
            loop Пока запуск активен
                G->>G: Сформировать сырые измерения сигналов
                G->>D: JDBC INSERT пакета и COMMIT
                D-->>G: Пакет сохранён
            end
        and Расчёты по расписанию
            loop Пока работает сервис аналитики
                B->>D: SELECT raw telemetry только для ограниченного dirty диапазона
                D-->>B: Исходные данные
                B->>B: Пересчитать интервалы и минутные rollups в staging
                B->>D: Коротко атомарно заменить active projection range
            end
        and Контроль запуска из UI
            W->>G: Запросить статус и прогресс
            G-->>W: Состояние запуска и ошибки
            opt Пользователь остановил запуск
                U->>W: Остановить генерацию
                W->>G: Запросить остановку
                G->>G: Прекратить генерацию после текущей записи
                G-->>W: Запрос остановки принят
            end
        end
    end
```

## 1. Управление структурой оборудования и настройками

Одна последовательность применяется ко всем CRUD-операциям. В предприятии создают линии и отключённые станки; станок можно сразу или позднее однократно назначить линии, после чего добавляют дерево компонентов разных видов, сигналы и настройки. Физическое удаление конфигурационных сущностей в MVP не выполняется.

```mermaid
sequenceDiagram
    actor U as Сотрудник
    participant W as Web-клиент
    participant B as Сервис аналитики
    participant D as PostgreSQL
    U->>W: Открыть структуру предприятия
    W->>B: Запросить предприятия и оборудование
    B->>D: SELECT структуры и настроек
    D-->>B: Структура оборудования
    B-->>W: Данные для отображения
    W-->>U: Показать иерархию
    loop Для предприятия, линии, станка, компонента, сигнала или настройки
        U->>W: Создать, изменить или отключить объект
        W->>B: CRUD-запрос
        B->>B: Проверить данные, связи и допустимость операции
        alt Операция допустима
            B->>D: Записать изменения и завершить транзакцию
            D-->>B: Изменения сохранены
            B-->>W: Результат операции
            W-->>U: Обновить структуру
        else Ошибка проверки
            B-->>W: Причина отказа
            W-->>U: Показать ошибку
        end
    end
```

## 2. Просмотр текущего состояния оборудования

Для демо используется периодический опрос только current read models. Это обновление с небольшой задержкой, а не гарантия жёсткого реального времени. Ответ содержит время измерений, `dataThrough`, время расчёта, `stale` и `recalculating`, чтобы UI отличал свежие значения от устаревших.

```mermaid
sequenceDiagram
    actor U as Сотрудник
    participant W as Web-клиент
    participant B as Сервис аналитики
    participant D as PostgreSQL
    U->>W: Выбрать линию, станок или компонент
    loop Пока открыт мониторинг
        W->>B: Запросить текущее состояние и показатели
        B->>D: SELECT signal/state current projections, показателей и ручных incidents
        D-->>B: Значения, качество и временные метки
        B->>B: Определить актуальность данных
        B-->>W: Состояние, скорость, активность, аварийные показатели
        W-->>U: Обновить мониторинг и показать актуальность
    end
```

## 3. Историческая аналитика и временная линия

Включает выбор периода, просмотр простоев, всплесков активности, аварий и скорости. HTTP-чтение всегда возвращает последнюю полную committed projection и никогда не запускает расчёт. Пользователь отдельно создаёт asynchronous recalculation job только после изменения правил или по явной команде пересчитать период либо всю историю.

```mermaid
sequenceDiagram
    actor U as Сотрудник
    participant W as Web-клиент
    participant B as Сервис аналитики
    participant D as PostgreSQL
    U->>W: Выбрать оборудование, период и показатели
    W->>B: Запросить историческую аналитику
    B->>D: SELECT результатов за выбранный период
    D-->>B: Доступные результаты
    B-->>W: Committed графики, интервалы и metadata актуальности
    W-->>U: Показать простои, активность, аварии и скорость
    opt Пользователь запросил явный перерасчёт
        W->>B: Создать PERIOD или ALL recalculation job
        B-->>W: 202 и идентификатор задачи
        loop До завершения задачи
            W->>B: Запросить состояние задачи
            B-->>W: PENDING/RUNNING/SUCCEEDED/FAILED и progress
        end
    end
```

## 4. Внесение сотрудником сведений об инциденте

Сотрудник может дополнить существующую аналитическую временную линию причиной или зарегистрировать инцидент вручную. Автоматически обнаруживаемых инцидентов в MVP нет. Ручная запись описывает факт и не переписывает исходную телеметрию.

```mermaid
sequenceDiagram
    actor U as Сотрудник
    participant W as Web-клиент
    participant B as Сервис аналитики
    participant D as PostgreSQL
    U->>W: Открыть инцидент или зарегистрировать новый
    opt Открыт существующий инцидент
        W->>B: Запросить сведения об инциденте
        B->>D: SELECT события и ручных сведений
        D-->>B: Карточка инцидента
        B-->>W: Сведения для формы
    end
    U->>W: Указать время, SETUP/PLANNED_STOP, причину и комментарий
    W->>B: Создать, изменить, закрыть или отменить инцидент
    B->>B: Проверить границы, ownership, overlap и eligibility
    B->>D: Сохранить сведения, автора и время изменения
    D-->>B: Сведения сохранены
    B-->>W: Обновлённая карточка; аналитика пересчитывается асинхронно
    W-->>U: Показать результат и связь с временной линией
```

## 5. Настройка, запуск, статус и остановка генерации

Предусловие: структура оборудования, компоненты и сигналы уже созданы через Analytics API. Scenario, GenerationRun, immutable snapshot, progress и terminal result сохраняются в общей PostgreSQL; генератор не дублирует CRUD оборудования и пишет raw только по существующим `signalId`.

```mermaid
sequenceDiagram
    actor U as Сотрудник
    participant W as Web-клиент
    participant G as Spring-генератор
    participant D as PostgreSQL
    U->>W: Открыть страницу генерации
    U->>W: Выбрать оборудование и настроить сценарий
    W->>G: Передать настройки сценария
    G->>D: SELECT конфигурации оборудования и параметров
    D-->>G: Конфигурация
    G->>G: Проверить сценарий и привязки
    G-->>W: Сценарий принят или ошибки проверки
    U->>W: Запустить генерацию
    W->>G: Создать запуск сценария
    G-->>W: Идентификатор запуска
    par Генерация в фоне
        loop Пока запуск активен
            G->>G: Сформировать сырые измерения сигналов
            G->>D: JDBC INSERT пакета в короткой транзакции
            D-->>G: COMMIT пакета
        end
        G->>G: Зафиксировать завершение или остановку запуска
    and Управление из UI
        loop Пока пользователь наблюдает активный запуск
            W->>G: Запросить статус запуска
            G-->>W: Прогресс, записанные данные и ошибки
            W-->>U: Показать состояние генерации
            opt Пользователь запросил остановку
                U->>W: Остановить генерацию
                W->>G: Запросить остановку запуска
                G->>G: Запретить новые пакеты после текущей записи
                G-->>W: Запрос остановки принят
            end
        end
    end
    W->>G: Запросить итоговый статус
    G-->>W: Завершён, остановлен или ошибка
```

## 6. Фоновая обработка новых измерений

Планировщик и calculation workers работают внутри приложения Analytics. Обработка идёт независимо от HTTP-запросов и Generator. Durable work задаёт ограниченные event-time окна; пересчёт и staging выполняются вне короткой публикационной транзакции. Затронутый диапазон заменяется атомарно, поэтому чтения получают прежнюю полную либо новую полную committed проекцию. Late-data boundaries и evaluator context определены в `spec-machine-state-projections/` и `spec-raw-telemetry-ingestion/`.

```mermaid
sequenceDiagram
    participant G as Spring-генератор
    participant D as PostgreSQL
    participant S as Планировщик backend
    participant C as Calculate service
    participant I as Incident service
    G->>D: Добавить пакет исходной телеметрии
    D-->>G: COMMIT
    S->>C: Запустить расчёт очередного интервала
    C->>D: SELECT измерений, состояний и правил расчёта
    D-->>C: Исходные данные
    C->>C: Рассчитать активность, скорость, простои и превышения
    C->>D: Записать и проверить staging range
    C->>D: Коротко заменить active range и завершить durable work
    D-->>C: Диапазон атомарно опубликован
    C-->>S: Расчёт завершён
```

## Границы ответственности

- Генератор пишет исходные измерения; Analytics читает их и пишет структуру, производные проекции и ручные сведения об инцидентах. Расчёт сам по себе не создаёт инциденты.
- Оба приложения используют один согласованный контракт таблиц и согласованные миграции. Проверки телеметрии выполняет писатель; ограничения целостности обеспечивает база.
- Генерация и расчёты выполняются в фоне. HTTP-запуск генерации не держит запрос открытым на весь сценарий.
- Для исходной телеметрии используются короткие пакетные транзакции и защита от повторной записи. JDBC или R2DBC сами по себе не устраняют дедлоки.
- Номинальный профиль, пределы нагрузки, SLO и минимальный стенд определены в `docs/bmad/specs/spec-mvp-load-slo/`; observability и его запуск — в `docs/bmad/specs/spec-observability-runtime/`.
- Сценарии прогнозирования, подключение реальной шины и ETL не входят в текущую демо-версию.
